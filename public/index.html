    网络配置
    
          
        
    
        
    决定实例的流量怎么走。一个配置可以给多个实例用，修改后这些实例一起生效。
    
        
    
        
    
          规则从哪来，出口怎么替换
          
    基础规则就是 Clash Verge 合成后的主规则，包括你在它的「编辑规则」页改的规则和订阅自带的规则。在 Clash Verge 里改规则后，用这些规则的配置也会跟着更新。
    
          
    优先级从高到低：SandGate 配置的额外规则 → Clash Verge「编辑规则」页的规则 → 订阅自带的规则。
    
          
    
            
    你想要的效果写在哪
    
            
              
    所有程序都这样走Clash Verge 的「编辑规则」页
    
              
    只有某个配置的实例这样走SandGate 配置的额外规则
    
              
    换掉某个配置的出口，规则本身不变SandGate 配置的替换出口
    
                
          
    
          
    替换出口只改你选的组。规则指向哪个组，就只有替换了那个组才会变。比如只换 🌐 Proxy 时，CDN 规则如果指向 US 组，图片、脚本等静态资源仍走美国；DIRECT 规则仍走真实 IP。
    
          
      
            
    • 只想让主要流量换 IP：替换 🌐 Proxy 就够了。
      • 
            
    • 想让代理流量都从同一个地区出去：把规则用到的组都替换掉。
      • 
            
    • 所有流量都走同一个 IP：选“全部走一个节点”。
      •

      运行一次 node bin/sandgate.js alias install 让 ~/.zshrc 加载这些命令。一个终端命令同一时间只指向一个实例：给另一个实例填同样的命令，会问你是否改过来，这就是切换账号；同一程序的其他实例卡片上也有“改用这个”按钮。改指向后，已经打开的终端里也立刻生效；新加的命令名要新开终端。从终端启动的实例用你当前的目录和参数，可以同时开多个，不会显示为“运行中”。
      
      
      
      程序能读写你的所有文件，网络也不由系统强制：走代理的流量走选定的出口，绕过代理的走 Clash 主规则。数据环境固定为共用数据：HOME 就是你的用户目录，没有分身；但参数里的 {data} 仍指向实例自己的目录，所以 Chrome 预设的 --user-data-dir 仍和主 Chrome 分开存放，Cookie 和登录状态也是实例自己的。适合 Chrome 这类自带沙盒的程序，这样它的沙盒和钥匙串都能保留，启动时会自动去掉 --no-sandbox 和 --use-mock-keychain。已有实例切换这个选项后，Chrome 的登录状态和保存的密码会读不出来，需要重新登录；可以先停止实例，用“清空数据”从头开始。不要用来运行不信任的程序。
